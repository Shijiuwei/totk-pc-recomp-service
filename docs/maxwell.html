Maxwell / NVN behaviour a port must reproduce

Reference for diagnosing graphics bugs. Each item: what Maxwell (GM20B, 3D class B197, compute B1C0) and NVN do, what Vulkan / AMD (RDNA4, our GPU0) do instead, how emulators and ports handle it, and the source. Items are ordered by how likely they are to cause visible artifacts. "Ours:" marks what our runtime does (grep-level look, see section 7; our code is cited by file and function). Licensing: yuzu/suyu are GPL, cited for behaviour only.

Source shorthands:

  • OGD: NVIDIA open-gpu-doc classes/3d/clb197.h, classes/compute/clb1c0.h (MIT-style), https://github.com/NVIDIA/open-gpu-doc/tree/master/classes. Offsets below are method offsets in clb197.h.
  • G80TEX: Mesa nouveau src/gallium/drivers/nouveau/nv50/g80_texture.xml.h (MIT), https://gitlab.freedesktop.org/mesa/mesa/-/blob/main/src/gallium/drivers/nouveau/nv50/g80_texture.xml.h.
  • RYU-SU: Ryujinx Ryujinx.Graphics.Gpu/Engine/Threed/StateUpdater.cs (MIT), mirror at 1.1.1137: https://git.dawidpotocki.com/mirror/ryujinx/plain/src/Ryujinx.Graphics.Gpu/Engine/Threed/StateUpdater.cs?h=1.1.1137.
  • RYU-SH: Ryujinx shader translator vendored at refs/MacNativeGames/vendor/ryujinx/src/Ryujinx.Graphics.Shader/ (Ryujinx 1.3.2, MIT). Paths below are relative to it.
  • NXN: nxnative's graphics notes, refs/nxnative/docs/agents/ (MIT). nxnative has rewritten them since; each row states the behaviour and fix it took from them.
  • MNG: refs/MacNativeGames @ b75be8cfa704df3701e86130c8ced268e79d6b11 (MIT); line numbers below are at that commit.
  • DK3D: refs/deko3d @ 373bfd43d8b2d805fa2eb7d406dbb823032df958 (zlib, fincs), the homebrew Maxwell driver for Switch. Written against the hardware, not the NVN API: what it programs is what the GPU needs. Paths relative to source/. .def files give methods as word indices (engine_3d.def); byte offset = index x 4, so 0x5A1 = OGD 0x1684. No conditional rendering, no provoking-vertex conversion, no 8-bit indices in it.
  • YZ-2305 / YZ-2306: yuzu progress reports May / June 2023, https://yuzu-mirror.github.io/entry/yuzu-progress-report-may-2023/, https://yuzu-mirror.github.io/entry/yuzu-progress-report-jun-2023/ (behaviour only).
  • VKSPEC: Vulkan 1.4 specification, https://registry.khronos.org/vulkan/specs/latest/html/vkspec.html; GLSL450: SPIR-V GLSL.std.450 extended instructions, https://registry.khronos.org/SPIR-V/specs/unified1/GLSL.std.450.html.

1. Render targets

#Maxwell / NVNVulkan / AMDEmulators / portsSource
1.1Colour target the fragment shader does not write keeps its old texel, even with blending enabled.Undefined value written/blended.NXN: zero write mask and no blend for unwritten outputs (reflection colors). Already fixed here.NXN; MNG games/totk/tests/metal_semantics/probe.m:5
1.2Unwritten vertex outputs read as (0, 0, 0, 1) in the next stage, including the unwritten components of a partly written output (VS writes xyz, FS divides by w).FS input with no VS output: interface mismatch, value undefined; an unwritten component of a written output is undefined (AMD: whatever the register holds, often 0).Ryujinx initialises exactly the components the next stage reads, but only when stages are linked (Translation/Translator.cs:212-227, NextInputAttributesComponents); position starts (0,0,0,1) (:259). NXN Link's Awakening: sun shadow lookups divided by w = 0, scene dim, no shadows. Ours: missing outputs padded with (0, 0, 0, 1), unlinked outputs initialised by translator patch 0006 (section 7, check 2).NXN
1.3Clears honour the scissor and the clear's own channel / stencil write mask, and may come between draws inside a pass. SET_CLEAR_SURFACE_CONTROL (0x10f8) has RESPECT_STENCIL_MASK, USE_CLEAR_RECT, USE_SCISSOR0, USE_VIEWPORT_CLIP0.vkCmdClearAttachments takes a rect but ignores the colour write mask; load-op clears are whole-attachment.NXN/MNG draw a triangle with the clear's mask (clear_color_tri, clear_ds_tri); TotK uses mid-pass, partial-mask and partial-scissor clears (NXN). yuzu: "red dot" was clears hitting the wrong RT index (YZ-2305, PR 10243). Hardware recipe (DK3D): CLEAR_BUFFERS (0x674 = 0x19d0) carries the colour channel mask (bits 2-5), depth (0), stencil (1), target id (6-9) and layer (10-20) in one word; ClearBufferFlags (0x43E = 0x10f8) is set once to `StencilMaskScissor (maxwell/gpu_3d_base.cpp:69), so every clear is cut by scissor 0 and its stencil bits by the stencil front write mask register, and DK3D's colour clear does not program ColorWriteMask (0x680). A stencil clear writes StencilFrontMask (0x4E7) and ClearStencil (0x368) just before the clear and restores the shadowed state after (gpu_3d_base.cpp:497-510). Multisample raster is switched off around a colour clear (:459, :465). Arrays: an MME macro repeats the clear for every layer (maxwell/clear_buffers.mme:5-22`). No pass concept: clears sit between draws. Ours: masked colour and stencil clears are skipped (check 3).
1.4Conditional rendering (SET_RENDER_ENABLE_A..C 0x1550-0x1558, NVN SetRenderEnableConditional) compares two 64-bit counters at addr and addr+16 on the GPU, in command order. TotK wraps nearly every clear in it. A TIMESTAMP report writes 0 to the counter field.VK_EXT_conditional_rendering tests one 32-bit word against zero.NXN: honouring it fixed the black 3D scene (light-volume depth never cleared). deko3d has no conditional rendering at all (no SET_RENDER_ENABLE in engine_3d.def), so it cannot settle the compare rule. Ours: evaluated on the CPU at record time; a report from an unfinished submission counts as 0 (check 5).OGD; NXN
1.5Depth mode is runtime state: nvnDeviceSetDepthMode near = -w (GL, NVN default) or 0. Register SET_VIEWPORT_Z_CLIP (0x0d7c) NEGATIVE_W_TO_POSITIVE_W / ZERO_TO_POSITIVE_W.Vulkan clips z < 0 unless VK_EXT_depth_clip_control negativeOneToOne.Ryujinx infers the mode from the viewport transform, falling back to the register (GetDepthMode, RYU-SU). NXN: wrong mode either clips everything (black window) or puts all depth in 0.5..1 (DOF blurs the screen). Ours: negativeOneToOne from NVN state. DK3D programs both halves: SetDepthMode (0x35F = 0xd7c) selects the pre-transform clip range, and the viewport transform maps z to [near, far] itself: scale z = 0.5 * (far - near) and offset z = 0.5 * (near + far) for -1..1, scale far - near and offset near for 0..1 (maxwell/gpu_3d_base.cpp:143-147, 336-343). Same maths as Vulkan negativeOneToOne.OGD 0x0d7c; NXN-64, NXN; DK3D maxwell/gpu_3d_base.cpp:136-147, 321-362
1.6Depth clamp / clip: SET_VIEWPORT_CLIP_CONTROL (0x193c) has separate PIXEL_MIN_Z/PIXEL_MAX_Z CLIP or CLAMP and geometry-clip modes.depthClampEnable also disables z clipping (unless VK_EXT_depth_clip_enable). RADV had a dynamic depth clamp driver bug causing TotK vertex explosions.Ryujinx: clamp = !(clip & DepthClampDisabled) (RYU-SU UpdateDepthClampState). yuzu disabled dynamic depth clamp on affected RADV (YZ-2305, PR 10262). DK3D has one switch, depthClampEnable, and writes VIEW_VOLUME_CLIP_CONTROL (0x64F = 0x193c) with 0x101A when on and 0x181D when off (default at setup is 0x181D); it labels the bits "todo: figure out what this actually does". Bits 3-4 (DepthClampNear/Far) are set in both values, bits 0-2 and 11 differ. There is no separate depth-clip toggle. The viewport near/far registers (Viewport array words 2-3) carry the clamp range and are swapped when far < near (:349-350). Vulkan clamp to [min, max] of the viewport depth matches.OGD 0x193c; DK3D maxwell/gpu_3d_state.cpp:42, gpu_3d_base.cpp:135-139, 349-350, engine_3d.def:621
1.7Depth formats: D24S8 is native; D24 quantises to 2^-24 everywhere in 0..1. Polygon offset units are in D24 steps for D24 targets; SET_DEPTH_BIAS_CONTROL (0x1110) DEPTH_FORMAT_DEPENDENT.RX 9070 has no D24S8 attachment; D32F has finer steps near 0 and a per-primitive exponent-based r. EQUAL / LEQUAL tests between a pre-pass and a later pass, and decal biases, behave differently.yuzu rescales depth-bias units when D24 is emulated as D32F; Ryujinx passes units / 2 (register is twice the API value) (RYU-SU UpdateDepthBiasState). MNG: D16 load-clear 0.5 → 32767 vs fragment 0.5 → 32768 made Ultrahand/Recall classification tiles visible. Ours: D24S8 → D32_SFLOAT_S8, bias not rescaled (check 4). DK3D writes PolygonOffsetUnits (0x56F = 0x15bc) as constantFactor * 2.0f, clamp to 0x61F, factor to 0x55B (maxwell/gpu_3d_state.cpp:148-157), confirming the x2 register.OGD 0x1110, 0x15bc, 0x156c; MNG docs/how-it-works.md:57-61; DK3D maxwell/gpu_3d_state.cpp:154
1.8Position invariance: identical position math gives identical depth across programs (pre-pass then EQUAL / LEQUAL).Only for outputs declared Invariant.Ryujinx decorates position Invariant (CodeGen/Spirv/Declarations.cs:571) and marks float ops NoContraction unless QueryHostReducedPrecision (CodeGen/Spirv/Instructions.cs:2047). NXN: Odyssey ground z-fought without it; LA's foliage drawn with depth EQUAL vanished when the pre-pass failed. Ours: translator default (all NoContraction).NXN
1.9Sampling a texture that is also a bound render target: Maxwell's texture cache is not coherent with ROP writes; NVN requires nvnCommandBufferBarrier(INVALIDATE_TEXTURE) between writing and sampling (methods INVALIDATE_TEXTURE_DATA_CACHE 0x1338, ..._NO_WFI 0x1288). Reading a different level/layer, or read-only depth while testing, is fine.Same image as attachment and sampled in one pass is a feedback loop: undefined unless VK_EXT_attachment_feedback_loop_layout; on AMD DCC/HTILE-compressed data is not readable by the sampler without decompression.yuzu: pixelated Ultrahand glow fixed with barriers on attachment feedback loops (YZ-2305, PR 10402). BotW black textures on GCN worked around with AMD_DEBUG=nohyperz (HTILE off) (https://git.openpunk.com/OpenPunk/yuzu/wiki/commit/bd401539420182cbbf8bc638b042536a7e690c3f). Ours: an NVN barrier ends the pass and inserts a full memory barrier; no detection of a sampled texture that is a current attachment (check 10). DK3D barrier recipe (maxwell/gpu_base.cpp:49-115): the ordering part and the cache part are separate. Ordering: Tiles = TiledCacheBarrier (0x3DF), Fragments = FragmentBarrier (0x378), Primitives = WaitForIdle (0x44), Full = gpfifo SetReference + new gpfifo entry with NoPrefetch, so later command and indirect-parameter fetch happens after everything finished. Tiles and Fragments need an implicit WFI before a cache invalidate. Caches (each opt-in): texture data InvalidateTextureDataCache (0x3DD, WFI) or ..NoWfi (0x4A2); shader InvalidateShaderCaches (0x369: instruction, global data, constant); descriptors InvalidateTextureHeaderCacheNoWfi (0x50A) + InvalidateSamplerCacheNoWfi (0x509); zcull 0x4B2; L2 gpfifo MemOpB L2FlushDirty + L2SysmemInvalidate. The texture-cache invalidate is its own flag; ordering alone does not refresh it. Every queue flush ends with image + shader + descriptor + L2 invalidation "to ensure the visibility of CPU updates between flushes" (:28-47): CPU writes into textures and descriptors reach the GPU at the next submit boundary, not mid-submit (2.2).OGD; DK3D maxwell/gpu_base.cpp:28-115
1.10Duplicate attachments: the same texture bound at two colour slots with write mask 0 on one does not interfere (ROP writes only enabled channels).Tile-based or compressed attachments may store the unwritten copy over the written one.NXN BotW G-buffer (c1 = c2, c3 = c4): leaves the duplicate slot unattached (rt_dup_slot).NXN
1.11Per-target write masks: RtColorMask[i], or entry 0 for all when RtColorMaskShared. SET_SINGLE_CT_WRITE_CONTROL (0x0f90). A colour target with format 0 is disabled.Per-attachment colorWriteMask.RYU-SU UpdateRtColorMask, IsRtEnabled ("Colors are disabled by writing 0 to the format").OGD 0x0f90
1.12sRGB render target views: NVN encodes on write when the view format is sRGB over a linear texture. Maxwell also has a global SET_SRGB_WRITE (0x15b8).Format of the attachment view decides; needs MUTABLE_FORMAT.NXN Mario: attaching the base texture stored linear values, picture darker. Ours: RT views take the view format (view_format).OGD 0x15b8; NXN
1.13Compressed and 3D targets: agl's GPU BC4 encoder renders blocks through an RGBA16UI view, one plane of a 32×32×32 BC4 3D texture per pass. NVN renders a 3D texture slice by slice.Needs BLOCK_TEXEL_VIEW_COMPATIBLE + EXTENDED_USAGE, 2D_ARRAY_COMPATIBLE.NXN shadow textures (bcrt_attach). yuzu: wrong block depth on 3D slices gave Gloom textures on terrain (YZ-2305, PR 10433). Already fixed here.NXN
1.14Draw with no render target (fragment shader only writes an SSBO, 1×1 viewport) runs normally.Needs an attachment-less pass with explicit render area.NXN bare_dims: cave ambient light came back. Ours: area of viewport 0 (vk_exec.c resolve_rt).NXN
1.15Window origin: NVN default lower-left (GL); TotK switches to upper-left. Y flip and scissor flip follow.Vulkan upper-left; negative viewport height to flip.Ryujinx flips scissor against screen height when Y-negate is on (RYU-SU UpdateScissorState).NXN
1.16Multiple viewports / scissors (16), selected by ViewportIndex output.Needs multiViewport and shaderOutputViewportIndex.Ours: one viewport, one scissor; differing scissors logged (nvn_api_cmd.c).OGD 0x192c
1.17Fragment output saturation per target: SET_PS_SATURATE (0x13a8) clamps output n to 0..1 or -1..1 in fixed function. NVN does not expose it (GLSLC emits .SAT in code).None.Not emulated by Ryujinx; listed so a clamp difference is not chased in the wrong place.OGD 0x13a8
1.18New memory reads as zero (fresh pool pages); feedback effects never clear their state texture.New image content undefined.NXN tex_zero_fill.NXN
1.19MSAA: nvnCommandBufferDownsample resolves; depth-stencil downsamples are copies the game does itself.vkCmdResolveImage colour only; integer formats pick one sample.NXN LA: stencil lost in the half-size depth copy, no AO.NXN

3. Shader math

#MaxwellVulkan / AMDEmulators / portsSource
3.1FMNMX and .SAT with NaN return the other operand / 0 (IEEE minNum). Games rely on this to stop NaN spreading (one NaN pixel blown up by bloom or temporal passes flickers or fills the screen).GLSL.std.450 FMin/FMax/FClamp: result undefined when an operand is NaN (NMin/NMax are the NaN-dropping forms). AMD hardware min/max usually drops NaN; the compiler may still assume no NaN.Ryujinx emits FMin/FMax/FClamp (CodeGen/Spirv/Instructions.cs:336, 956, 972; saturate = FClamp 0..1, Instructions/InstEmitAluHelper.cs:419-423). 3.2FMZ multiply mode (FMUL/FFMA/... field Fmz, .FMZ): 0 × anything = 0, including Inf/NaN (DX9 rule).IEEE: 0 × Inf = NaN.Ryujinx decodes Fmz (Decoders/InstDecoders.cs:306-309, 1901) but no emitter reads it. Ours: same. Census needed (check 13).RYU-SH
3.3Denormals: per-instruction .FTZ.AMD flushes fp32 denormals by default; VK_KHR_shader_float_controls sets it per shader.Ryujinx ignores .FTZ. Low risk.RYU-SH (no Ftz use in Instructions/)
3.4Warp size 32: SHFL, VOTE, S2R LANEID, ballots are 32-bit.AMD RDNA runs wave32 or wave64 per shader (the driver chooses; RADV fragment default wave64); VK_EXT_subgroup_size_control requiredSubgroupSize = 32 fixes it.Ryujinx adapts lane masks to QueryHostSubgroupSize() (default 32, IGpuAccessor.cs:218; Instructions/InstEmitWarp.cs:72, 106, InstEmitMove.cs:175-185). 3.7Integer division does not exist (compiled to XMAD/IMAD sequences); MUFU.RCP(0) = +Inf, LG2(0) = -Inf.Same IEEE edge cases through 1/x, Log2.Low risk.—
3.8FP64 in some TotK cutscene shaders.No FP64 on some hosts.yuzu FP64 → FP32 (YZ-2306, PR 10693); ours: softfloat64 job flag (tools/xlate/Program.cs QueryHostSupportsShaderFloat64).—
3.9Integer vertex inputs read as raw bits (bone indices R8UI).Float-declared inputs convert integers.NXN Mario: stretched characters; re-translated with uint inputs. Ours: attribute types passed to QueryGraphicsState (Program.cs).NXN
3.10BFE / BFI fields past bit 31 (as PTX bfe / bfi): a field that runs past bit 31 is cut there; one that starts past it extracts 0 (signed: bit 31 repeated) and inserts nothing. UltraTears saw the Depths walls and ground missing on the Steam Deck and a Linux RX 570 (RADV). Ours: clamped where the field is not a constant inside the word (translator patch 0012). RX 9070 on Windows drew the Depths the same before and after.PTX ISA bfe, bfi

7. Checks for our runtime

Grep-level look on 2026-10-22, statuses updated 2026-10-26; "saw" is what the grep and short reads showed, not a test result.

  1. Provoking vertex. Vulkan draws flat outputs from the first vertex, NVN from the last. vk_pipeline.c enables provokingVertexLast and chains VkPipelineRasterizationProvokingVertexStateCreateInfoEXT{LAST_VERTEX} in create_graphics; without the feature it logs that flat outputs come from the first vertex. Fixed.

  2. Unwritten vertex outputs. spirv_add_outputs (vk_pipeline.c) adds outputs initialised to (0, 0, 0, 1) for FS inputs the VS lacks. Our translator never links stages, so Ryujinx's InitializeVertexOutputs would initialise no user output; translator patch 0006 initialises the unlinked outputs. Fixed.

  3. Masked clears. vk_exec.c skips colour clears with a partial channel mask (W_CLEAR_MASK); clear_ds skips stencil clears with a partial mask (W_STENCIL_MASK). TotK issues such clears (NXN). Check the log for colour clear with channel mask and stencil clear with mask. DK3D (1.3) confirms what the replay must do: colour clear = scissor 0 + channel mask, stencil clear = value & mask merged under the front write mask; so a draw with colorWriteMask / stencilWriteMask set to the clear mask is the exact equivalent. Missing.

  4. D24 → D32F. vk_formats.c maps D24S8 to D32_SFLOAT_S8_UINT; vk_exec_draw.c record_fixed passes NVN units unscaled. Depth EQUAL passes and decal offsets can z-fight. Look at: per-pass depth-test op histogram, EQUAL passes against D24 targets. N/A for TotK: a census of the field and fight saves (2026-10-22) saw depth targets 0x34 (DEPTH32F) and 0x32 (DEPTH16) only; biased draws (units -5 and 1, factor -0.5 and -0.2) are on DEPTH32F.

  5. Counters and conditional rendering. vk_exec_xfer.c (as of 2026-10-22): every report writes {0, time}; SAMPLES_PASSED is always 0; a condition is read on the CPU at record time and an unfinished report reads 0. Grep the NVN log for counter types other than TIMESTAMP; any occlusion-driven visibility (flares, culling) is off. Fixed 2026-10-22: SAMPLES_PASSED counts come from Vulkan occlusion queries between RESET and REPORT (vk_exec_xfer.c, ~4 queries per frame in the field, ~21 in a fight); the game's CPU reads them (guest f_70010c3298) to cull objects.

  6. Subgroup size. The translator assumes 32; RDNA4 may run fragment shaders in wave64. vk_caps.c and vk_pipeline.c pin_subgroup32 pin stages to 32 lanes with VkPipelineShaderStageRequiredSubgroupSizeCreateInfo where subgroupSizeControl allows it, and otherwise tell the translator the GPU's own size (TOTK_VK_SUBGROUP_PIN=0 forces that). Fixed.

  7. Images aliased onto GPU-only pool memory. vk_texture.c bind_pool_memory binds each VkImage into its pool allocation; textures are keyed by address plus descriptor, and each new image starts UNDEFINED (init_image). Two descriptors over the same storage, or bytes written through a buffer, do not see each other's data on AMD. Check: count distinct keys per address per frame. Risk (yuzu PR 10418 class).

  8. GPU writes into CPU-visible pools. note_gpu_write (vk_exec_xfer.c) stamps pages when the fence completes, so a texture sampled later in the same submission keeps its old upload; GPU-only pools are skipped. MNG saw at most one buffer copy per frame in TotK, so low priority. Risk.

  9. Index buffers. vk_exec_draw.c op_draw_idx: byte indices widened on the CPU at record time, skipped in device-local memory; restart_for: a non-all-ones restart index logged and dropped. Census (2026-10-22): 130-170 byte-index draws/frame widened on the CPU, 0 device-local, 0 non-all-ones restarts. OK; VK_KHR_index_type_uint8 (supported) would drop the CPU cost.

  10. Feedback loops. Census (2026-10-22): 425/frame (field) to 667 (fight), G-buffer material/decal shaders sampling the 1600x900 targets of the open pass. The terrain G-buffer pass reads its own albedo, normal and R32F targets at the fragment's pixel; on the RX 9070 the reads returned stale data as ~16x14 px dark rectangles on the ground, and the sage spirit next to Link was not drawn. vk_exec_draw.c (feedback loops) now detects such a draw: with VK_EXT_attachment_feedback_loop_layout and dynamicRenderingLocalRead the target moves to the feedback layout and a by-region barrier precedes the draw; without them the pass restarts behind a full barrier (TOTK_FEEDBACK). Fixed.

  11. Border colours. vk_texture.c make_sampler: custom colour only with customBorderColorWithoutFormat, else transparent black; integer formats use the float path. Confirm the RX 9070 reports the feature (grass map needs 0.5). OK if supported.

  12. Dual-source blend. vk_pipeline.c blend_factor maps SRC1 factors; Program.cs QueryGraphicsState always passes dualSourceBlendEnable = false, so no Index 1 output exists. Log pipelines with SRC1 factors. Mismatch if used.

  13. FMZ / NaN. Count FMUL/FFMA/FMUL32I/FFMA32I words with the Fmz field set (Decoders/InstDecoders.cs:1901 bit positions) in build/v121/shaders/; FMin/FMax/FClamp NaN results are undefined (3.1). Census (2026-10-22): FMZ in 1 instruction of 12397 shaders, FTZ in 12241 shaders, FMNMX in 7457. The translator emits GLSL.std.450 FMin/FMax (Ryujinx GenerateMinimum), not NMin/NMax. FMZ: no fix needed. FMNMX: OK (RX 9070 test: FMin/FMax(NaN, 1) = 1 both orders, FClamp(NaN, 0, 1) = 0).

  14. Point size / line width. Census: SetLineWidth 4.5 ~1/frame (2 line draws into a 144x144 R8 target), SetPointSize 5 ~14/frame; 4 point VS rely on it. Point size: translator patch 0008 reads it from the support buffer, fixed. Line width: 1 px, non-default values logged (nvn_ext.c), mismatch, minor.

  15. Block height. nvn_tex.c truncates like NVN (2.1). DK3D rounds up (dk_image.cpp:446); every other step matches. OK.

  16. Depth mode and clamp. vk_pipeline.c create_graphics (negativeOneToOne from nvn_depth_minus_w, depthClampEnable from NVN state). DK3D agrees on the z maths (1.5) and the clamp switch (1.6). OK.

  17. Depth bias argument order. vk_exec_draw.c record_fixed (units, clamp, factor); DK3D takes the same three and doubles units for the register (1.7). OK.

  18. Sampler LOD. vk_texture.c make_sampler. OK.

  19. Viewport / scissor arrays. Single viewport (vk_exec_draw.c record_fixed), extra scissors logged. Census: 0 differing. OK.

  20. Depth-compare sampling in compute (VUID-vkCmdDispatch-None-06479): one compute shader samples a 4x4 R32F CPU-written placeholder through an R32_SFLOAT view with compare on, ~1/frame. Needs a D32 copy. Minor.

  21. Report timestamps: unit and instant. write_counter (vk_exec_xfer.c) writes host ns * 12 / 625 (19.2 MHz ticks) at fence completion for every report; nvnDeviceGetTimestampInNanoseconds converts back with the same factor (nvn_ext.c). DK3D: GPU ticks convert at 625/384 ns (614.4 MHz), TIMESTAMP is written when the ROP has retired the earlier work, TIMESTAMP_TOP when the command processor reaches it (4.2). Two consequences for the engine's GPU time (dynamic resolution and speed follow it): (a) if the 1.2.1 consumer scales raw report ticks with its own constant rather than the NVN conversion call, our 19.2 MHz unit is 32x off from the hardware's; find that consumer before fixing the unit; (b) the delta needs vkCmdWriteTimestamp2 with TOP_OF_PIPE for TIMESTAMP_TOP and BOTTOM_OF_PIPE for TIMESTAMP, per submission segment, converted to whichever unit (a) shows. Mismatch (instant); unit unverified.
